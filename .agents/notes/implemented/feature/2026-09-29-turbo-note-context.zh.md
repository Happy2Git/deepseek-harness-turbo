# Agent Note: Turbo 任务笔记与无摘要模型的上下文替换

Status: implemented

[English](2026-09-29-turbo-note-context.md) | 中文

## Problem

Turbo 面向重复调查和简短证据报告。额外摘要模型增加调用延迟，也可能遗漏任务约束；没有可恢复记录便丢弃历史，会损失证据。

## Decision

可选的[上下文入口](../../../../packages/session-query/tool-session-query/README.zh.md#turbo-context-windows)复用持久化会话日志作为唯一笔记存储，并复用已有历史工具检索证据。成功的笔记工具结果驱动可回放投影。替换只在完整工具步骤持久化后开始，沿用现有上下文替换与 token 影子计价协议。原始事件仍可查询。官方预设保留原有压缩策略。

消息来源标记替换及提醒内容；旧读取方无需理解可选投影，也会保留这些消息及其替换封装。该来源属于已发布 Session 格式内的归因类新增，已记录持久化变更确认。

Turbo 将面向模型的查询消费方作为 `session-query/` 下的正式功能包，因为随附的第 5 个预设必须能在不依赖实验包的情况下加载。预设仅提供搜索和精确读取工具（`includeTrace: false`），每次请求省去两个关系 schema。调查指引要求先给出有用回答或调用直接工具，不强制启动 scout 或写笔记。受管理的 scout 使用 caller 结果投递，取消时等待释放，不在有界工具结果之外另外通知主 agent。

## Alternatives considered

**额外调用摘要模型。** 可能生成更丰富的摘要，但会增加用户要求省去的模型请求。持续笔记将维护工作放入普通任务推进过程。

**独立的文件系统笔记数据库。** 重复持久化日志的职责，并增加第二套恢复与授权路径。现有工具结果与历史索引已满足当前需求。

**没有新笔记便丢弃历史。** 会移除当前上下文中有关中间修正和未完成动作的唯一记录。因此替换要求有效且大小受限的新笔记，并逐字保留首次及最新用户输入和指令消息。

## Consequences

替换省去摘要模型调用，但笔记维护和证据检索仍消耗 token。重建请求可能降低缓存复用。笔记可能遗漏中间约束；agent 需要持续更新，存在疑问时读取原始证据。缺少模型容量元数据时无法自动处理上下文压力，但仍可显式替换。缺少持久化或保存失败时阻止破坏性替换；最终保存失败会停止当前轮次，此时原始历史已经保存。

真实 Web 组合测试覆盖恢复、搜索、自动阈值、缺少笔记、笔记超限、取消与持久化失败。无需密钥的上下文快照覆盖模型可见输出；这些检查不证明真实模型的延迟收益。

Turbo 启用可选 trigram 分词器，改编自 [Happy2Git session-query-trigram 分支](https://github.com/Happy2Git/deepseek-harness/tree/feat/session-query-trigram)。中文片段可找回连续文本中的证据。短词扫描转义字面通配符，匹配与排序统一处理 ASCII 大小写。其他预设保留 unicode61。未引入 sidebar-search-locate 分支，其搜索限于当前可见对话，无法找回 Turbo 已替换的工具证据；模型工具已经返回精确事件序号。
